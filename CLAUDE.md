# CLAUDE.md

## What this repo is

This repository (`main`) is the phylogenetic tree viewer as a reusable library: framework-free, tree-shakeable, and usable from React or any
other frontend, by GBIF and by others. The research and the comparison of other viewers live on the `research` branch. Do not bring them back here. See
[README.md](README.md).

## Working conventions

- Develop on feature branches off `main`. Do not open pull requests unless asked.
- Check licences before adding a dependency. GPL/AGPL matter for embedding in gbif.org, and the packages are Apache-2.0. The viewer and
  tree-ops have no runtime dependencies; keep it that way unless there is a strong reason.
- Prefer web-native, browser-only solutions: the target is a static frontend fetching tree files from a remote archive.
- Any UI should follow GBIF design tokens (see the `gbif-design-tokens` skill if available) through the theme and CSS custom properties,
  never hard-coded in the core.
- Claims in `docs/design` must say where they came from. Mark anything not verified as **unverified**.

## Domain notes

- Formats: Newick (most common), Nexus (may wrap trees plus a taxa/translate block), phyloXML, NeXML.
- Tip labels are the join key to GBIF occurrences/taxa. Matching can be exact or fuzzy and must be explicit about unmatched tips.
- Large trees need level-of-detail rendering (collapse/aggregate clades, Canvas/WebGL), not one SVG element per node.

## Repository layout

npm workspaces (Node >= 22.7):

- `packages/viewer`: `@gbif-phylo/viewer`, the core.
  - [docs/api.md](packages/viewer/docs/api.md) is the API reference.
  - [docs/internals.md](packages/viewer/docs/internals.md) covers the frame pipeline, invariants, module map, how to extend it, and the cut goldens.
- `packages/react`: `@gbif-phylo/react`, `<TreeView>`.
- `packages/tree-ops`: tree operations. No DOM, no rendering.
- `packages/io`: Newick/NEXUS parsers and `TreeModel`.
- `examples/vanilla`: the framework-free example (controls, events, a custom popup and column, a dark theme), checked by
  `tests/browser/scripts/check-vanilla-example.mjs`.
- `examples/react`: the React example with tree operations, checked by `tests/browser/scripts/check-node-menu.mjs`.
- `examples/explorer`: the tree explorer, the styled showcase of the library and the counterpart of the playground (its look started from Reactree; its README is a table of control to API), checked by
  `tests/browser/scripts/check-explorer.mjs`.
- `examples/table`: the table view (TBrowse-like: fixed rows that scroll, the tree as one column among data columns, a header row with resize), on the
  public API only; its README lists the gaps in the core it works around. Checked by `tests/browser/scripts/check-table.mjs`.
- `examples/unrooted`: the page of the unrooted layout spike (#42): `unrootedLayout` of one tree drawn on a plain canvas, every branch, no zoom.
  It imports the layout from `packages/viewer/src` by relative path (not exported; a spike exception to the public API). Checked by
  `tests/browser/scripts/check-unrooted.mjs`.
- `examples/shared`: the tree catalogue (`catalogue.json`) and the loading helpers (fetch, gzip, `remote`, FASTA) of the playground and the explorer. A folder, not a package.
- `examples/playground`: the plain viewer with every option, theme token and control in a panel (settings in `src/settings.ts`, kept in the
  URL), checked by `tests/browser/scripts/check-playground.mjs`.
- `site`: the demo site's hub. `npm run build:site` (`scripts/build-site.mjs`) builds it with the pages in `site/src/examples.json` and
  their data into `site-dist/`; Vercel runs it (`vercel.json`). Checked as served by `tests/browser/scripts/check-site.mjs`.
- `examples/no-build`: plain HTML using the single-file builds (`<package>/browser`, `dist/browser/*.js`, made by
  `scripts/bundle-browser.mjs` in the viewer and io builds) through an import map; checked by `tests/browser/scripts/check-no-build.mjs`.
- `tests/browser`: a test page exposing `window.__spike`/`__spike2`/`__customTree`, the browser checks and the benchmarks.
- `data/`: test trees (`real-ladder/`, `rich/`, `synthetic/`), each with its own README, manifest and scripts. Large files are git-ignored
  and fetched or regenerated by script. Keep committed files small, and record licence and provenance for every new file.
- `docs/design`: measurements and design notes carried over from the research, and [library.md](docs/design/library.md) on the
  library's design.

## Code

- **Package entry points.** Each package's `exports` has a `@gbif-phylo/source` condition pointing at `src/*.ts`. Tests (`node --conditions=@gbif-phylo/source`), the
  examples and the test page (Vite `resolve.conditions`) and typecheck (`customConditions` in `tsconfig.base.json`) use the source.
  Consumers get `dist/` (per-file ES modules from `tsc -p tsconfig.build.json`, `.ts` imports rewritten to `.js`).
- **Root scripts:**
  - `npm run check`: typecheck, ESLint 9 with no warnings allowed, Prettier check, every workspace's `node:test` suite.
  - `npm run build`: build every package.
  - `npm run check:packages` (after a build): publint, the tarball contents, and tree shaking. Small apps are bundled from `dist/`, and the
    modules they must not contain are asserted absent. Add a scenario when you add an optional module.
  - `npm run format`: Prettier.
- **Viewer tests.** In `packages/viewer`, `npm test` runs:
  - unit tests of the core modules with a fake canvas and document,
  - the cut golden test,
  - the radial regression `scripts/check-radial-cut.mjs` as a child process.

  `node --experimental-transform-types scripts/capture-cut-golden.mjs` rewrites `test/cut-golden.json` after a deliberate change of the
  cut. Otherwise a diff of that file is a regression.
- **Browser tests.**
  - `npm run test:browser -w tests/browser` (`-- --only test,vanilla,react,explorer,playground,table,unrooted,no-build,site` to pick pages) builds each page, serves it with `vite preview` on a free port and runs its check:
    - the test page runs `check-radial-ui.mjs`;
    - the vanilla example runs `check-vanilla-example.mjs`;
    - the React example runs `check-node-menu.mjs`;
    - the explorer runs `check-explorer.mjs`;
    - the playground runs `check-playground.mjs`;
    - the table view runs `check-table.mjs`;
    - the unrooted spike runs `check-unrooted.mjs`;
    - the no-build example runs `check-no-build.mjs`. It builds the packages and serves static files itself, without Vite.
    - the site runs `check-site.mjs`. It runs `scripts/build-site.mjs` and serves `site-dist/` with vercel.json's URL rules.
  - Each check also runs against a dev server with `--url`.
  - Cloud sandbox: headless Chromium at /opt/pw-browsers/chromium-1194 (Playwright `executablePath`). There is no GPU, so use it for functional and relative tests; final frame rates need a real browser.
  - Do not use `pkill -f`.
- **API conventions.**
  - Controls and popups are controls (`BaseControl`: listeners through `listen` / `domListen`) and use only the public API. The overview is the exception: it uses `viewerInternals`.
  - Built-in reactions to clicks and hovers listen with `{ asDefault: true }`, so apps can `preventDefault()` them.
  - Visual values are `TreeTheme` tokens (CSS `--phylo-*`), never constants in the drawing code.
- **Rules of the core.** No recursion and no per-node allocation in the cut, draw and hit code. The two cut loops in `src/lod.ts` are separate copies on purpose (measured, see the header of `src/projection.ts`), so change them together.
- **Data scripts** are pure Python 3 standard library, iterative, no recursion. Run them with `python3 -I`.
