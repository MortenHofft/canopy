# CLAUDE.md

## What this repo is

A research/prototyping repo for adding phylogenetic tree visualisation to gbif.org. See [README.md](README.md) for the goal and [docs/](docs/) for findings.

## Working conventions

- Default branch is `main`. Develop on feature branches; do not open pull requests unless asked.
- Research claims in `docs/` must say where they came from. Mark anything not verified against primary sources (docs, repo, paper) as **unverified** rather than stating it as fact.
- Compare candidates with [docs/evaluation-framework.md](docs/evaluation-framework.md): gates first, no single total score, every cell has a capability (Y/P/N/?) and an evidence level (M measured, S source, D documented, C claimed, N not found, U unlooked). Record version and date.
- Keep the decision-relevant criteria in [docs/goal.md](docs/goal.md) up to date; the comparison in [docs/comparison.md](docs/comparison.md) is judged against them.
- Prefer web-native, browser-only solutions: the target is a static frontend fetching tree files from a remote archive.
- Check licences before recommending a dependency (GPL/AGPL matter for embedding in gbif.org).
- Any UI prototype should follow GBIF design tokens (see the `gbif-design-tokens` skill if available).

## Domain notes

- Formats: Newick (most common), Nexus (may wrap trees plus a taxa/translate block), phyloXML, NeXML.
- Tip labels in the supplied tree are the join key to GBIF occurrences/taxa; matching can be exact or fuzzy and must be explicit about unmatched tips.
- Large trees need level-of-detail rendering (collapse/aggregate clades, Canvas/WebGL), not one SVG element per node.

## Repository layout

- `docs/`: goal and criteria, recommendation, comparison, per-candidate research in `docs/research/`.
- `data/`: test trees (`real-ladder/`, `rich/`, `synthetic/`), each with its own README, manifest and scripts. Large files are git-ignored and fetched or regenerated by script; keep committed files small (see `data/README.md`) and record licence and provenance for every new file.

## Code

Data scripts are pure Python 3 standard library, iterative, no recursion; run with `python3 -I`. The custom candidate (`spikes/custom`, TypeScript; Node >= 22.7; start with its [README](spikes/custom/README.md) and [docs/api.md](spikes/custom/docs/api.md)) has, run from that folder:

- `npm run dev` (port 5306), `npm run build`, `npm run preview -- --port 5306`.
- `npm run typecheck`, `npm run lint` (ESLint 9, no warnings allowed), `npm run format` / `format:check` (Prettier), `npm test` (`node:test` under `test/`: unit tests of the pure core modules, the cut golden test, and the radial regression script as a child process), `npm run check` (typecheck + lint + format:check + test). CI (`.github/workflows/custom-renderer.yml`) runs `npm run check` and `npm run build` on Node 22 for changes under `spikes/custom`, `spikes/shared`, the Parquet reader and `data/synthetic`. A `test:browser` script and a CI browser job are being added; see `package.json` and the workflow for what exists.
- `node --experimental-transform-types scripts/check-radial-cut.mjs` (core regression, no browser, about 2 s; also part of `npm test`); `node scripts/check-radial-ui.mjs` (needs the build served on port 5306); `scripts/capture-cut-golden.mjs` rewrites `test/cut-golden.json` after a deliberate change of the cut (otherwise a diff of that file is a regression); `scripts/check-parquet-source.mjs` (needs Parquet files and two servers); `bench/*.mjs` before/after benchmarks (need the build served; see docs/results/custom.md).
- Rules of the core: no recursion and no per-node allocation in the cut, draw and hit code; the two cut loops in `src/core/lod.ts` are separate copies on purpose (measured, see the header of `src/core/projection.ts`), so change them together.

The renderer reads its tree through a `TreeSource` (`src/core/source.ts`; `<TreeView tree=...>` wraps it in an `InMemorySource`, `source=...` takes another); `src/parquet/` holds a `ParquetSource` proof of concept (dev page `parquet.html`, check `scripts/check-parquet-source.mjs`, how to regenerate the git-ignored Parquet files: docs/results/treesource-slice.md).
