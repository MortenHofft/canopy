# Example: the tree explorer

The styled showcase of `@canopy`, and the counterpart of the [playground](../playground): the playground is the low-level API demo (every
option and theme token in a panel); this is what an application built on the library looks like when it is styled, with toolbars, tools,
a node menu, panels and an export menu around `<TreeView>`. The drawing, the events and the views come from the viewer, the edits and the
views of the tree from `@canopy/tree-ops`. It is also the seed of a drop-in widget. Its look started from
[Reactree](https://github.com/vaaloo/reactreejs) (reactreejs 1.0.3), and most icons in `src/icons.tsx` are Reactree's, used under its MIT
licence; the click action icons in `src/icons-click.tsx` are paths copied from react-icons (each under its set's licence, in `THIRD_PARTY_NOTICES`); Inspect, Fit, Subtree, Collapse (also on Collapse to 50 clades), Expand all, Up one level and Back to root in `src/icons-feather.tsx` are Feather's (MIT, copied, two with an arrow mirrored); the newer controls have icons drawn for this repository in `src/icons-ours.tsx`.

```
npm run dev -w examples/explorer    # http://127.0.0.1:5309 (?tree=<id> from src/trees.ts, ?theme=dark, ?debug=1)
```

The browser check is `tests/browser/scripts/check-explorer.mjs`; it drives every control and reads the result back from the viewer (headless
Chromium).

## What the explorer demonstrates

Each control and the API behind it.

| Control | API |
|---|---|
| **Tree picker**: every tree of the playground's catalogue (21, in its four groups) and two of our own, from 6 tips to 2.4 million, and *A file from your computer…* (Newick or NEXUS, gzipped or not; not kept in the URL). Trees are parsed in a Web Worker, so the page responds while a large one loads | `catalogue.json` shared with the playground; `fetchBytes` of `examples/shared/data.ts` (a `remote` URL when `/data/<path>` is not served: the 1.5M and 2.4M OTL trees); the bytes or the file are parsed by `parseInWorker` of `@canopy/io/worker` (gzip inflated in the worker). The tree shown stays while the next one loads; the loading line names the step (`onProgress`) and **Cancel** aborts it (`signal`: the worker is terminated) and goes back to the tree shown, as a load that fails does (its error stays until the next pick); with no tree shown the list names nothing, so any entry can be chosen again (#4) |
| **Click action Inspect** (the default): the node menu | `<TreeView nodeMenu>`: the core `NodeMenu`, with items for what was clicked. Internal node: Info, Collapse, Show only, Reroot here, Colour…. Collapsed clade (a click on its branch, or Enter; a click on its triangle expands it, see the drill-down below): Expand, Info, Show only, Colour…. Tip: Info, Reroot here, Colour…. Root (of the tree, or of a clade shown alone): Info, Collapse to 50 clades (over 50 tips), Expand all (while a clade is collapsed), Colour…, and the ones of a clade shown alone. One line per item, no descriptions; styled as the inspector (the same panel, header and close button, `.phylo-node-menu*` classes in `explorer.css`). Its close button, a click outside and Escape close it. Enter on the keyboard cursor opens it too. Opening it selects the node, so the selection ring stays on it while the pointer is in the menu. The hover box gives the node's tips, support, branch length and first and last tip (colours `--ex-tooltip-bg` and `--ex-tooltip-text`) |
| **Selection**: a click selects the tip or clade (a ring), Info opens the inspector on it; both stay across Layout and Phylo/Clado switches, which keep the tips in view where they were (the viewer's `switchView: 'keep'`), not the selection | `<TreeView selected onSelectionChange>` (the viewer's `setSelected`, a click selecting by default); a tool's click calls `preventDefault()` so it selects nothing |
| **Click action** select (first control of the View row; an icon beside each action, and on a phone only the icon and a caret, the native list still naming the action): Inspect, Collapse, Subtree, Reroot, Colour | `onNodeClick` / `onTipClick` (with `preventDefault()`: no selection), and `nodeMenu` returns `null` while an action other than Inspect is chosen. Collapse collapses a clade (a collapsed one opens), Subtree is Show only (`focusOn`), Reroot roots the tree at the tip or clade (`ops.reroot`; not a collapsed clade, and not inside a clade shown alone), Colour paints with the palette 5 swatches on each time, so two clades painted in a row are far apart, and a click on a clade that has a colour takes it off. Escape goes back to Inspect. **Shift or Ctrl held** changes the action for the moment: to Inspect, or to Subtree when it is Inspect already; the select shows it while the key is down (`modHeld` and `action` in `Explorer.tsx`; a key listener on `window`, cleared when the window loses focus). A click on the root with Collapse chosen opens a menu of Collapse to 50 clades and Expand all (`nodeMenu` answers for Collapse too, and the click does not `preventDefault()`), as the root's menu does |
| **Show only**, **Back to root**, **Up one level** (icons only, with a tooltip; on a wide screen the first of the View row, left of the click action and a divider, on a phone in the second row) | tree-ops `focusOn`, `focusUp`, `showFocus`. A navigation, not an edit: not in Undo; an edit carries the focus over with `remapFocus` |
| **Summaries of collapsed clades**: the label "Name · 12,345 tips" (or "12,345 tips"); the Info panel lists the highest named clades inside | The label is the viewer's default `formatCollapsedLabel`, with the explorer's `cladeLabel` (no `mrcaott…` names). The Info panel calls `namedDescendants(snapshot, clade, { formatLabel, cladeLabel }, { max })` on a snapshot of the tree (`new InMemorySource(tree).snapshot()`): the shallowest named clades inside, breadth-first, at most 12 in the Info panel, with a work cap so a huge clade costs no more than a small one; "…" or "and more" when it stopped early. The Info panel also gives the clade's tips |
| **Click a collapsed clade**: expand it in place; **Show only** in its menu: jump into it | The open question of #57 (expand or jump on a click) is settled here as: a click on the triangle expands, and the menu (a click on the clade's branch, or Enter on the keyboard cursor) offers Show only. The click is `mergeAutoCollapse(tree, collapsed, { root: clade, maxRows: 20 })`: the clade opens with its own overview of about 20 rows, and a clade whose children don't fit gets one row per child. Expand in the menu still opens the clade whole (only its own id leaves the `collapsed` set), so the two differ. Show only is `focusOn` plus `mergeAutoCollapse(..., { root: clade, maxRows: 50 })`, with the clade itself kept in the collapsed set, so Back to root (the whole tree again, `navigate(NO_FOCUS)`) and Up one level walk out to the view as it was. The click calls `preventDefault()` (`expandsOnClick` in `Explorer.tsx`: a pointer click with `kind: 'summary'` and `collapsed: true`), so neither the menu nor the selection follows; the hover box gives the clade's tips, support, branch length and first and last tip |
| **Collapse** a clade, **Collapse to 50 clades** and **Expand all** (⋮ menu; the first only on a clade of more than 50 tips, the second once a clade is collapsed) | the `collapsed` prop (`viewer.setCollapsed`, a view in the viewer: the tree is not changed and ids are the full tree's). Collapse to 50 clades is tree-ops `mergeAutoCollapse(tree, collapsed, { root, maxRows: 50 })`: the clades collapsed inside the clade shown are replaced by `autoCollapse`'s overview, the others kept (#57) |
| Rectangular / circular; **Phylogram / Cladogram** (⋮ menu, a radio pair) | the `layout` and `branchLengths` props |
| **Truncate names** (⋮ menu) | `options.formatLabel` (28 characters and an ellipsis above 30, Reactree's rule) |
| **Search** (⌘F, count, ↑ ↓, Enter) | the `highlighted` prop for the matches and `focus` to centre the current one (a clade: `zoomToNode`). A regular expression over the tip labels and the names of the internal nodes (clades); every match is counted, and the tips of a matching clade are highlighted |
| **Highlight style** (band / dim / both) | `options.highlightStyle`; `dim` is the default here (what does not match fades to `--phylo-dim-opacity`, the tip labels stay at full strength) |
| **Midpoint root**, **Ladderize ascending / descending** (⋮ menu, by number of tips) | tree-ops `midpointRoot`, `ladderise(t, { order, by: 'tips' })` |
| **Tooltips** (⋮ menu) | `<TreeView tooltip>`: the hover box is `false` while it is off |
| Reroot here (node menu), Undo (⌘Z) | tree-ops `reroot`; a history of trees, each edit a function returning a new tree. Colours, collapsed clades and the focus follow the tips (`followClades`, `remapFocus`) and the view stays (`treeMap`, the op's node map) |
| **Undo** (⌘Z, no button) within a memory budget, **Reset** (⋮ menu, only once there is an edit) | tree-ops `treeBytes`: the trees kept between the one as published and the current one stay within `undoBudget` (64 MiB; `?undo-budget=<bytes>` on this page), the oldest dropped first. A tree larger than the budget has Reset only, with a note saying why. Reset and Undo keep the view through the edits' inverse maps (`invertMap`, `composeMaps`) |
| **Colour…** in the menu (12 swatches, Erase), **Clear selection** (the legend's last row) | the `clades` prop (the innermost clade's colour wins). No label is set, so the legend names a clade by its node |
| **Show support**, **Show branch length** (⋮ menu; one at a time) | `options.nodeLabels` (`'support'` reads `tree.support`, `'length'`); the numbers are formatted by the viewer's default `formatNodeLabel` (support to 2 decimals at most). The Carangaria MCC tree keeps its support as `[&posterior=…]`: `trees.json` sets `supportKey` and `trees.ts` parses it with `{ annotations: true }` and copies `supportFrom(tree, 'posterior')` into `tree.support` |
| **Align labels** (⋮ menu; leaf labels in one column, or on one circle in the circular layout, with leader lines) | `options.alignLabels`; the leaders are `--phylo-leader-*` theme tokens |
| **Minimap**, **Legend** (⋮ menu) | the viewer's `OverviewControl` and `Legend` controls from `defaultControls({ overview, legend })`; their look follows `--phylo-surface` and `--phylo-border`. The legend names the coloured clades, has a × (`onClose`, which hides it as the menu's Legend does) and ends with **Clear selection** (`actions`: takes every colour off) |
| **Export…** (⋮ menu: it opens the export list in place of the menu, with Back): PNG at 1×, 2×, 4×; Newick; NEXUS | `viewer.toBlob({ scale })` (the theme's background, the pane's grey, as on screen); `toNewick` / `toNexus` from `@canopy/io`. With a clade shown alone (Show only), Newick and NEXUS give that clade (`ops.subtree`, files `subtree.nwk` / `subtree.nex`, the list says Subtree) |
| **Toolbar tooltips** (`data-tip` on the buttons of the View row): instant, one box under the button the pointer or the keyboard is on, in the colours of the hover box on the tree (`--ex-tooltip-bg`, `--ex-tooltip-text`). A native `title` would wait about a second | `onPointerOver` and `onFocus` on the row (`showBarTip`); `position: fixed`, as the row scrolls and would clip it |
| Tooltips ("Click for actions", "Set as root", "Paint Red", "1/2 Select first branch") | the `tooltip` prop rendering our own content, with `tooltipBare` so the viewer's box adds no chrome |
| Dark mode (`data-theme="dark"` on `<html>`) | the `--phylo-*` properties change with it; `options.themeObserver: 'document'` watches `class` and `data-theme` on `<html>` |
| Popover corners | one radius, `--ex-popover-radius`, for the toolbar menus, the inspector, the node menu, the colour palette, the search, the hover box and the toast; what sits inside one (menu items, close buttons) takes `calc(var(--ex-popover-radius) * 0.6)` |
| Pane background | `--phylo-background: var(--ex-surface-10)`: an opaque canvas in the pane's grey; no dotted grid. `dark` is derived from it |
| Hover ring that grows in (Reactree's) | `options.hoverAnimation` (on by default) and the theme's `--phylo-hover-ring-duration`; off when the system asks for reduced motion |
| Resize handle | the pane's height; the viewer follows its container |
| **Debug panel** (`?debug=1`, e.g. `/explorer/?debug=1` on the site), under the tree pane: the build (commit and branch), the tree (its label and id, or a file's name; tips, nodes, rows, collapsed clades), the layout, the canvas in CSS px and `devicePixelRatio`, the viewport, kx, ky and the tip pitch, and the last frame's level of detail (the budget in force and the option it comes from, `auto` or a number, and with the radial `auto` budget the 4° wedge limit in px, marked when the budget has passed it). **Copy view** copies the view as JSON, **Copy URL** a link with `?view=` that restores it: the tree, layout, label size, aligned labels, the level-of-detail options and the collapsed clades, then the viewport once the tree is laid out. A note says when the canvas size, the build or the tree differs from the copied one (a file cannot travel in the URL: load it with the picker and its view applies) | the `frame` event (read a few times a second), `getStats()` (`frameMs`, `cutMs`, `visited`, `listLength`, `minPxUsed`, `minPxLimit`, `budget`, `budgetHit`, `budgetRetries`, `forced`, `reduced`, `scale`, `kx`, `ky`), `getViewport()` / `setViewport()` (after `ready`), `options` (`minCladePx`, `drawBudget`, `lod`, `showSummaries`, `radialMaxNodes`, `interactionLOD`, `labelDensity`, `radialOpening`, `dprCap`), `size`, `layout.rows`, `getTheme().labelSize`. The tip pitch is `ky` in rectangular (px per row) and in radial the arc between rows on the outermost tip circle, `kx · 2π · (1 − radialOpening) / layout.rows`. The build is the `__BUILD__` define of `vite.config.ts` (`scripts/build-info.mjs`, as the site hub's footer) |

### Large trees

Nothing is switched off on a large tree. Search highlights every match: on the 2.4 million tips of OTL the label scan takes about 0.1 s
and highlighting a million matches about 0.05 s plus a frame of under 30 ms (headless, `docs/design/highlight-cost.md`). Measurements of the whole-tree actions are in the CHANGELOG entry for #54.

## Notes

- **Where the look differs from Reactree.** The look is kept as its own tokens (`--ex-*`), not GBIF's, so that it stays recognisably this
  example's. The viewer still takes every colour from CSS custom properties. The palette and export menu sit inside the component, not
  portalled to `<body>`.
- **No vector export.** The viewer draws on a canvas, so the menu has PNG, Newick and NEXUS, not SVG or PDF.
- **Labels only where they fit.** The viewer shows labels only where they fit (`labelDensity`), so a 135-tip tree at the fitted view has none
  until you zoom in or raise Height ([#24](https://github.com/MortenHofft/canopy/issues/24)).
- **Undo** is a history of trees owned by this component, bounded by memory ([#44](https://github.com/MortenHofft/canopy/issues/44)): about 45 to 60 steps of a 10k-tip tree, two of the 190k-tip GTDB tree, Reset only from about a million tips (figures in [docs/design/undo-memory.md](../../docs/design/undo-memory.md)). Views are not in it: Show only and collapsing. Undo keeps the clade shown (it follows the tips through the inverse map).
- **Colour… is a palette, not a submenu.** `NodeMenuItem` is a flat list (`id`, `label`, `hint`, `disabled`, `onSelect`), so *Colour…* opens the
  explorer's own palette for that one clade, at the click, with focus in it.
- **Toolbar width.** One row, and a second only when it has something in it (the note that Undo is off, and on a phone the buttons for a clade shown alone). Narrower than about 1250 px a row scrolls sideways.
