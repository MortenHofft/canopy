# Changelog

## Unreleased (2026-10-21: the library replaces the research on `main`; the research is on the `research` branch)

- **Nodes are numbers everywhere** (#30). **Breaking** for `<TreeView>`: `clades` is `{ node: number, colour, label? }[]` (was `{ nodeId: 'n<id>' }`), `collapsed` is `number[]`, and the handle's `zoomToNode`, `locateNode` and `nodeBounds` take a number. The events (`TreeEvent`, so also `TreeNodeEvent`) lose `nodeId`, the `'n<id>'` string form of `node`: use `node`. A node is the preorder id of the tree the viewer holds, the same number as in tree-ops' `map` and `TreeModel`, so an id from a click goes straight back. Tips can still be named by label (`highlighted`, `focus`, `focusTip`, `locateTip`). An id that is not a node of the tree (a string such as `'n12'`, a fraction, a negative id, or for a tree in memory an id past the last node; a partial source only checks the form) passed to `setClades`, `setCollapsed`, `setTree`'s `clades` / `collapsed`, `zoomToNode`, `locateNode` or `nodeBounds` is still ignored, now with a `console.warn` instead of silently. The rule is in one place in `docs/api.md` ("Naming nodes"). `examples/explorer`, `examples/react`, `examples/vanilla` and the test page drop the `slice(1)` / `'n' +` conversions.
- **Striped summaries** (#59, second part). New option `summaryStyle: 'solid' | 'striped'` (default `'solid'`, nothing changes) fills level-of-detail summaries (triangles, fans, polytomy and run bands) with fine stripes in the direction the hidden branches would run: rectangular, horizontal, about one per hidden row and at least `summaryStripeGap` px apart; radial, along the rays from the root, spaced by angle. New theme tokens `summaryStripeColour` (`''` = `summary`) and `summaryStripeGap` (default 3 px), with `--phylo-summary-stripe-colour` and `--phylo-summary-stripe-gap`. Clades collapsed by the app (`setCollapsed`, #29) stay solid unless the new option `stripeCollapsed` is true. Dimming (#22) applies as to the solid fill; the overview strip stays solid; a summary with room for fewer than two stripes stays solid. The stripes' width and alpha are set so their mean darkness is the solid fill's (width `max(1, a * pitch)`, alpha `a * pitch / width`, `a` the solid alpha, dimmed too; within 12% measured at pitches 3 to 20 px). `summaryStripeGap` below 1 is taken as 1. Radial rays form one grid over the fan's whole extent and only those at visible angles are drawn (every 2nd, 4th, ... past 256), so panning does not shimmer. Summaries whose stripes would be more than eight gaps apart stay solid. The overview strip stays solid by design. Segments are collected into one reused buffer and stroked in batches (no allocation per node; rectangular generates only the visible rows, radial at most 256 rays per fan). Because the cut only summarises clades under `minCladePx`, most summaries are too small for stripes at the default 3 px; `minCladePx` 12 or more shows them. Frame times at the fit view (headless Chromium, no GPU, mean JS draw time per frame over 40 frames, solid vs striped; `tests/browser/bench/stripes-bench.mjs`): GTDB 190k at 3 px 3.7 / 3.8 ms rectangular and 1.5 / 1.3 radial (almost no stripes), at 14 px 0.39 / 0.57 and 0.46 / 0.57 (40 to 70 summaries striped, one stroke each); OTL 100k at 3 px 2.7 / 2.6 and 1.4 / 1.9, at 14 px 0.43 / 0.38 and 0.61 / 0.66: up to about 0.2 ms more, noise included. The playground has the controls (Collapsed clade fill, default solid, Stripe colour, Stripe gap, Stripe clades collapsed by the app too); the explorer, the styled showcase, defaults to striped (with `minCladePx` 14 while on), with a Stripes button.
- **`<TreeView tooltip>` no longer calls the tooltip function with a stale hover event** (found by the review of #54). The last hover event was kept and passed to the function on every render, also after a new tree (Show only, collapse by support) had changed the node ids and after the box had hidden, so an app that looked the node up threw. The event is now dropped when the tooltip hides (the pointer leaves, a click, `treechange`) and is passed only while it belongs to the tree shown. **tree-ops `collapseBySupport` and `collapseShortBranches` take `{ extend: true }`**: the contracted edge's length is added to its children's, so every tip keeps its distance from the root and a dated tree stays ultrametric (unit test on the Carangaria MCC tree). The explorer, `examples/react` and the playground use it on ultrametric trees. The catalogue and the loading helpers of the playground and the explorer moved to `examples/shared/`.
- **Explorer styling** (#63, #64, the review of #54). One system font (`--ex-font: system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif`) for the page, the controls and the tip labels (`--phylo-font-family`), and `--ex-mono` for numbers read as numbers (the inspector, the clade tip count, slider values, search and support counts); bold is 600 or 500, not 700. The dotted background is gone: `--phylo-background` is the pane's grey, so the canvas is opaque, `dark` is derived from it (the hand-set `--phylo-dark` is removed), and PNG export needs no background argument. The View row keeps Search and Export pinned at the right and fades the end that has more when it scrolls (a `Scroller`; the Edit row fades too). Copy Newick's clipboard fallback returns the keyboard focus to where it was.
- **The explorer is brought up to date with the library** (#54, #46). `examples/explorer`, the styled showcase, now has: the node menu (`<TreeView nodeMenu>`) when no tool is active (a click or Enter opens it instead of collapsing; items by node kind; tools keep their direct action; the hover box says "Click for actions"); Show only this clade with Back and Up one level (tree-ops focus, as `examples/react`); Collapse by support with a threshold (`collapseBySupport` with `keep`, so clades collapsed by hand stay collapsed); ladderise by tips / depth / height (#49); the highlight style (band / dim / both); support as percent (`formatNodeLabel`); Align disabled in radial until #52; the viewer's overview and legend controls; an alignment column with `width: 'fill'` and `treeWidth: '40%'`; PNG export at 1×, 2× and 4× (`toBlob({ scale })`). Its tree picker lists every tree of the playground's catalogue (shared JSON, grouped as there, the `remote` URL and gzip as in `examples/shared/data.ts`) plus its own extras; nothing is disabled on large trees, and search is one regular expression capped at 5,000 matches. New icons are in `src/icons-ours.tsx`; the README is now a table of control to API. `scripts/build-site.mjs`: a page's `data` in `examples.json` may be a list of catalogue files. Undo is untouched (#44) except that each step also keeps the clade shown.
- **The focus ring of a label follows the label** (#62). The ring is the viewer's outline on the focused DOM anchor of a tip label. Anchors were repositioned on full-quality frames only, so during a drag, wheel or pinch (reduced frames, until `refineMs` after the last input) the ring stayed where it was while the canvas moved, and it also showed after a mouse click. Now `LabelOverlay.follow` moves the focused anchor on every frame and parks it off screen when its label is not drawn, and the rings (anchor and tree root) are CSS in `viewer.css`, `:focus-visible` only, instead of inline styles set once at `focusin`. A theme, label-size or font change no longer drops focus from a label (`clear(true)`). Check: `check-vanilla-example.mjs`.
- **Length labels: one placement rule at every zoom** (#53). A length is centred on the visible part of its horizontal branch when the text plus `max(3, nodeMarkerSize / 2 + 1)` px on each side fits, else it is not drawn; it is never placed at the node. The clearance now covers the node marker (it was a fixed 3 px). A node pushed out of view to the right (a stub in the draw list) keeps its length on the visible part of its stem instead of losing it. Tips get no label, as documented. The placement the issue reported came from the old Reactree `NodeLabels` control still deployed on `main` (it labelled tips and fell back to the node when the parent's position was null); the core `nodeLabels` never did that.
- **`examples/reactree` is now `examples/explorer`, the tree explorer.** It started as a Reactree look-alike to test the library's flexibility; it is now a styled example of the full API, an alternative to the playground and the seed of a drop-in widget. Package `@gbif-phylo/example-explorer`, component `Explorer`, CSS `--ex-*` / `ex-` (was `--rt-*` / `rt-`), test hook `window.__explorer` (was `__reactree`), check `check-explorer.mjs`, `--only explorer`, demo page `/explorer`. `/reactree` redirects to it (`vercel.json`). Behaviour is unchanged; Reactree stays credited for the look and the icons (MIT).
- **Collapsing a clade is a view in the viewer, not a data edit** (#29, option 1: the collapsed clade's rows are freed). **Breaking:** `viewer.setCollapsed(nodeIds)` and `<TreeView collapsed>` now take internal nodes of the tree the viewer shows (ids of the full tree, the same ids as `clades` and the events). Before, they marked tips of a copy built with tree-ops' `collapseClades`. Each collapsed clade is one summary (triangle or fan) on ONE row, never opened by the level of detail, ending at its deepest tip, so a dated tree stays dated and the axis keeps "time before tips" (#19 for this route). Layout: `Layout.rows`, `rowStart` / `rowEnd`, `rowOfRank` / `rankOfRow` / `rowNode` (null while nothing is collapsed: the cut goldens and the cut cost are unchanged), so the viewport `y`, the radial angle step, columns, `focusTip`, the keyboard cursor, the overview, highlight bands and `setTree`'s view keeping all work in rows. A click or hover on a collapsed clade is `kind: 'summary'`, `node` = the clade, new `collapsed: true` on the event. The clade is labelled with its name (`cladeLabel`) or "N tips" at the end of its triangle. Columns draw nothing on its row. `focusTip` on a tip inside one focuses the clade; `locateNode`, `nodePosition` and `nodeBounds` of a node inside one are `null`. Collapsing keeps the window's scale (no refit, no new renderer); a fitted view is fitted again. Removed: the tip-triangle drawing of the old `setCollapsed`, `COLLAPSED_W` and the aligned-label allowance for it. Not supported on a partially loaded source. `examples/react`, `examples/reactree` and `examples/playground` drop `collapseClades` and the id translation for collapse (focus and collapse-by-support stay tree-ops views); collapse by support leaves the nodes the viewer collapsed alone through the new tree-ops option `collapseBySupport(t, x, { keep })` (also `collapseShortBranches`; a set, an array or a predicate of node indexes). A collapsed clade shows its own `nodeLabels` support or length on its stem. Custom column renderers keep the rank contract: `draw()` is called once per stretch of consecutive visible ranks with `oy` shifted (`ColumnFrame.rankOfRow` is informational). Highlights inside a collapsed clade give one band and one ring and bold its label; the screen-reader list and the cursor announcement say "collapsed"; `zoomToNode` of a hidden node frames the clade.
- **Zoom limits and the tree/columns split** (#38, #39).
  - New option `maxTipSpacing` (default `'auto'`, 1.85 em rounded to whole px: 24 px at the default label size) replaces the fixed 500 px per row and 20,000 times fit scale; the view never goes below the fit; `Infinity` leaves only the old values as hard ceilings. **Default behaviour changes:** rows can no longer be zoomed beyond 24 px at the default label size. The x limit is unchanged.
  - `rowHeight` accepts `'auto'` and `'<n>em'`. The label density thresholds and `focusTip`'s least row height scale with `labelSize` (unchanged at the default 13 px).
  - New options `maxViewWidth` (default 1.6) and `treeWidth` (`'auto' | px | '<n>%'`); columns take `width: 'fill'`.
  - Playground: Max tip spacing, Max horizontal zoom-out, Tree width, Alignment fills the width.
  - Not done: a draggable divider, label ellipsis.

- **`reroot` and `midpointRoot` keep support that exists only in `tree.support`** (#48). Support moves with the edges from the `support` array (array first; the label's number is read only where `support` is NaN), so a BEAST posterior copied in with `supportFrom` survives "Set as root". Names stay in the labels, a moved edge takes its label's number text as written with it, and no number is written into a label that had none. `subtree` and `showFocus` also drop a label-only support number from the new root's label. `prune`, `collapseBySupport`, `collapseShortBranches` and `collapseClades` read `support` only and were not changed.
- **tree-ops `ladderise(t, { by })`** (#49). `by: 'tips' | 'depth' | 'height'` (default `'tips'`, output unchanged). `'depth'` is the most nested path from a child to a tip in nodes, `'height'` the longest path below the child in branch length (the child's own edge is not counted: crown height or age, so sibling ties on dated trees stay ties; missing or negative lengths count as 0; heights within 1e-6 of the greatest are equal; without lengths every edge counts 1, so it equals depth). Ties go to the other measures in a fixed order (depth: tips, height; height: tips, depth), then the input order (`order: 'decreasing'` reverses the tie-break measures too); `'tips'` keeps going straight to the input order so existing results do not change. Unknown `by` or `order` values throw a RangeError. One reverse-preorder pass computes the measures in use. The playground does not expose ladderise, so there is no UI.
- **`viewer.setTree(tree | source, { map?, view?, clades?, highlighted?, collapsed? })`** (#27). A new tree no longer re-creates the renderer. Controls, listeners, options, theme overrides and the canvases stay; layout, hit index, clade classes, highlights and column data are rebuilt. With the `map` of a tree-ops operation (or, with `view: 'keep'`, by tip label) the view stays on the tips that were in view, at the same scale (rectangular: by rank; radial: by angle); it fits when none survives (a tip that is gone counts as the nearest ancestor that survived, so collapsing the clade in view keeps the view on the triangle; when that ancestor is the whole tree it fits). A window equal to the current one no longer stops a running animation, so a controlled `viewport` prop does not break `fit(true)`. A new `treechange` event (`{ map }`) makes `Search` rebuild its index, `Legend` redraw and `NodeMenu` / `Tooltip` close. `clades`, `highlighted` and `collapsed` go in the same call, so no frame draws the old colours on the new tree; clades and collapsed marks default to the current ones sent through `map`. `<TreeView>` hands a new `tree` / `source` to `setTree` (only a switch between the two, or `options.softwareCanvas`, re-creates the renderer) and has a `treeMap` prop to keep the view; `onReady` fires once per renderer. `examples/react` and `examples/reactree` pass the operation's map (composed with `invertMap` / `composeMaps` for the collapsed view and for Undo) and drop their refit workarounds. A theme set by hand with `setTheme` now survives an edit.
- **API ergonomics from the Reactree look-alike** (#23; items 1, 2, 3, 5, 6 and 8).
  - `updateTheme(patch)` merges into the theme overrides; `setTheme` still replaces them.
  - New option `themeObserver: 'media' | 'document' | 'none'` (default `'media'`, as before). `'document'` also watches `class` and `data-theme` on `<html>` and calls `refreshTheme()`.
  - `fitViewport()` returns the window `fit()` would go to, without moving.
  - `toBlob({ type, scale, background })` draws the view into an offscreen canvas at a chosen scale, over the theme background unless told otherwise.
  - `Tooltip({ bare: true })` and `<TreeView tooltipBare>` drop the box chrome.
  - `tests/browser/README.md` documents how examples expose the viewer to browser checks.
  - `examples/explorer` uses all of them and loses its MutationObserver, its `fit(false)` round trip, its canvas compositing and its tooltip CSS overrides.
  - Not done: stretch sliders (item 4, low priority) and a draw-list iterator (item 7, belongs with #16).
- **Theme or option** (#32). The rule is written down in `docs/api.md` and the headers of `types.ts` and `theme.ts`: the theme is how things look (colours, px sizes, opacities, font family and style, all `--phylo-*`), options are what is shown and how the viewer behaves. The `ViewerOptions` and `TreeTheme` fields were checked against it, and the exceptions are listed with their reason; a few look constants in the drawing code are listed as known gaps. `italicLabels` moved to the theme as `labelFontStyle` (`'italic'` by default, `--phylo-label-font-style`, which the tooltip, node menu and search list also follow), and `alignRowGap` moved to the theme (`--phylo-align-row-gap`). Reactree sets the label style in its CSS. The playground has both under Theme.
- **Node labels** (#16). Option `nodeLabels: 'none' | 'support' | 'length' | ((node, tree) => string | number | null)` (default `'none'`) and `formatNodeLabel(value, kind)` (default: support to 2 decimals, lengths to 3 significant digits; show 0.95 as 95 with your own). Drawn by the core from the draw list (`drawNodeLabels` in `draw.ts`, one pass, at most 600 labels, 300 radial, no allocation per draw-list entry; the text of a node that passes the geometry tests is formatted, also when it then fails the width test): only expanded internal nodes, never inside a summary, never for a collapsed-clade tip (so the length `collapseClades { extend }` gave it is not shown), and only with room: the rows (rectangular) or the node's arc (radial) at least `LABEL_MIN_PX[labelDensity]` apart and the text fits the branch. Support sits left of the node above its branch, a length is centred on the branch (radial: along it, upright like tip labels). Dimmed with `highlightStyle` `'dim'`/`'both'`. Theme tokens `nodeLabelSize` (10), `supportColour` and `lengthColour` (`''` = `muted`), CSS `--phylo-node-label-size`, `-support-colour`, `-length-colour`. `internalSupport(label)` and `defaultFormatNodeLabel` are exported. `TreeData` has an optional `support` array (`TreeModel` and tree-ops results have it) that `'support'` reads before the label. Posterior (and any support kept as an annotation, #17): `tree.support.set(supportFrom(tree, 'posterior'))`, or the function form (api.md, "Node labels"). `examples/reactree` drops its `NodeLabels` control for the option and shows the posterior on the Carangaria MCC tree; the playground has the option, a "Support as percent" switch and the three tokens. Frame time with labels off is unchanged (one string compare per frame); with them on it follows the draw list, not the tree (gtdb-100k, headless Chromium without GPU, median of 3 runs of 20 forced frames: 40 rows in view, 137 primitives, 0.31 ms per frame off, 0.50 ms with 3 support labels; radial at the fit view, 1909 primitives, none with room: 1.83 ms off, 1.8 to 2.1 ms on; rectangular at the fit view it returns at once below the density threshold).
- **Clade names** (#34). The legend names a coloured clade by its node's name (the label without its support value, through `formatLabel`) with the tip count after it, and falls back to "Clade of N tips" when there is none. The viewer has a `cladeLabel(node, tree)` option (node: full-tree id) for what counts as a name (hide OTL's `mrcaott…` labels, look a name up); `Legend` may override it. The node menu title, the default tooltip and the keyboard announcement use the same rule (`cladeName` and `internalName` are exported). The legend follows `formatLabel` changes. The playground no longer passes its own label, and strips `_ott\d+` on OTL trees.

These changes made the spike's custom renderer into the first library form. Nothing is published yet, and the package names are placeholders.

- **Packages.** npm workspaces: `@gbif-phylo/viewer`, `@gbif-phylo/react`, `@gbif-phylo/tree-ops` and `@gbif-phylo/io` (moved out of the spike's shared code). Each is ES modules with declarations and source maps, built per file, and has no side effects except the viewer's CSS.
- **`TreeViewer`.** It replaces `TreeRenderer` and takes one object: `new TreeViewer({ target, tree | source, options, theme, columns, controls })`.
- **Events.** `on` / `once` / `off` replace the callbacks object. There are default actions with `preventDefault()`, and new events for options, theme, clades, highlights, resize, source changes, ready and destroy.
- **Controls.** A control layer, and `BaseControl` for your own. Built in: `Zoom`, `Fit`, `LayoutToggle`, `Search`, `Legend`, `OverviewControl` and `defaultControls()`. The `overview` option is removed; the overview is now a control.
- **Overlays.** `Overlay` pins an element to a node. `Tooltip` and `NodeMenu` moved from React into the core.
- **Alignment colours.** Residue colours are theme tokens (`residueHydrophobic` ... `residueProline` for protein groups, `residueA/C/G/T` for nucleotides, `residueOther`; CSS `--phylo-residue-*`), with light and dark defaults. An alignment column has `alphabet: 'auto' | 'protein' | 'nucleotide'`; nucleotides no longer use the amino-acid colours (A and C were the same). Tokens may be any CSS colour (resolved on a probe canvas, alpha dropped); `dark` now follows the merged background, also after `setTheme`. New exports `residueColours(theme, alphabet)` (the table that is drawn, as `#rrggbb`), `residueGroups`, `detectAlphabet`. `examples/reactree` draws its legend from them. Closes #21.
- **Custom columns.** `kind: 'custom'` with a `ColumnRenderer`.
- **tree-ops: `swap(t, a, b)` and `reorder(t, node, order)`.** Exchange two sibling branches, or give a node's children in any order (a permutation of them; `RangeError` otherwise). `rotate` stays. `examples/reactree`'s Swap now works inside polytomies, and its tree list has `edge-polytomy`.
- **Theme.** Canvas sizes and opacities are now tokens. The theme can come from `--phylo-*` CSS custom properties (`themeFromCss`, `refreshTheme`). There is `viewer.css` for the DOM and an optional `gbif.css`.
- **`<TreeView>`.** New `controls` prop. `theme` holds overrides only. `TreeNodeEvent` is the viewer's `TreeEvent`, so `tipRange` is now `tipStart` / `tipEnd`.
- **No build step.** Single-file browser builds `@gbif-phylo/viewer/browser` and `@gbif-phylo/io/browser`, and `examples/no-build`, a plain HTML page with an import map, plus its browser check.
- **Examples and checks.** A framework-free example. Browser checks for the test page and both examples. A package check covering publint, the tarball contents, tree shaking and sizes.
- **Review fixes.** These come from an adversarial review of the branch.
  - The browser checks fall back to Playwright's own Chromium, as on a CI runner (`tests/browser/scripts/chromium.mjs`).
  - A control has one viewer: adding it to a second viewer removes it from the first.
  - The wheel over a control zooms the tree instead of scrolling the page, except inside lists marked `data-phylo-scroll`. (The overview handles its own wheel, see #33.)
  - `<TreeView>` applies only the options whose prop changed, so a layout chosen with `LayoutToggle` is no longer reverted.
  - The viewer's element holds the `role="tree"` element and the control layer as siblings, so controls and popups are no longer inside the tree role. New `treeElement` and `focus()`.
  - A listener removed during an emit is no longer called by it.
  - `TreeTheme.dark` is documented as informational.
  - Builds clean `dist/` first, and the package check fails on output without a source.
  - `<TreeView>`'s default controls no longer bundle every control: 31.4 kB gzip instead of 34.3 kB.
- **tree-ops map helpers.** `followClade` / `followClades` find where a clade went after an operation by its surviving tips (`TreeInput` only, with `onSplit: 'drop' | 'keep'`), `invertMap` and `composeMaps` turn and chain node maps, and `remapFocus` can take the operation instead of a callback. `examples/react` and `examples/reactree` use them instead of their own `moveColour` / `moveNode` and inline map inversions.
- **Demo site** (2026-10-22). A hub page (`site/`) linking a playground with every option, theme token and control
  (`examples/playground`, which also shows only a clade, collapses clades and collapses by support with tree-ops) and the Reactree look-alike, built with their data by `npm run build:site` for Vercel (`vercel.json`), and
  checked as served (`check-site.mjs`). The large OTL trees come from the `data/otl-large` branch at build time.
- **Collapsing a dated tree** (issue #19). `collapseClades(t, nodes, label?, { extend })` lengthens each new tip by the clade's height (`true`/`'max'`, `'mean'` or `'min'`), so a collapsed clade of a dated tree still ends at the present and the shown tree stays ultrametric. `examples/react` and `examples/reactree` use it when the tree is ultrametric, and their browser checks assert that the axis stays "time before tips". `collapseBySupport` also makes a dated tree non-ultrametric, but because it drops the contracted edge, so the fix is a different one and it is not changed. The viewer's axis inference is unchanged.
- **Annotations in `@gbif-phylo/io`** (#17, 2026-10-22). `parseNewick` / `parseNexus` take `{ annotations: true }` and keep BEAST `[&k=v]` and NHX `[&&NHX:k=v]` comments in `tree.annotations`, a sparse side table (node and edge) with numbers, strings and `{a,b}` arrays, `column(key)` and `remap(map, before, after)` for tree-ops results (edge annotations follow their edge through `reroot`). Off by default: parse time is unchanged (gtdb-190k 9.4 MB: median 213 to 228 ms before, 209 to 223 ms after; a 1.2 MB BEAST tree 18 ms before and after; with annotations on 44 ms). `supportFrom(tree, 'posterior', pick?)` gives support from an annotation without changing `tree.support`; showing it as node labels is #16. `parseNewick` alone grows by about 2.7 kB minified (6.3 to 9.0 kB) because the reader is part of the parser. `toNewick` / `toNexus` accept `annotations: true`.
- **Root length written** (#17). Plain `toNewick` and `toNexus` now write the root's length when it has one (`(A,B):3;`), which changes the output of every export of such a tree.
- **Found by the Reactree look-alike** (`examples/explorer`, 2026-10-22).
  - A transparent or translucent `--phylo-background` works: the page shows through. The canvas has an alpha channel only while the background is not opaque (an opaque one keeps the faster opaque canvas; a theme change swaps the canvas), and is cleared before each frame. Before, frames were drawn over each other.
  - `addControl` keeps a `pointer-events` the control's element already has inline, so a control laid over the whole tree can let clicks through.
  - Nested clade colours: the innermost clade wins, whatever the order of `setClades` / the `clades` prop (it was the later entry).
  - `@gbif-phylo/io` has `toNexus`: a NEXUS file with a taxa block and the tree.
- **`TreeViewer` unit tests** (#25). `test/viewer-harness.mjs` builds a real viewer in Node (`makeViewer(tree, init)`) over the fake DOM, with a recording 2D context, `requestAnimationFrame`, `ResizeObserver`, `matchMedia` and `getComputedStyle`. Tests cover `setClades`, `addControl`, the frame order on an opaque and an alpha canvas, the canvas swap on a theme change, and `setTheme` / `refreshTheme`.
- **Aligned tip labels** (#35). Option `alignLabels` (default `false`): in a rectangular phylogram all tip labels start in one column right of the farthest tip, with a dotted leader line from each tip. Theme tokens `leaderColour` (default `muted`), `leaderDash` (`1 3`), `leaderWidth` (1) and `leaderOpacity` (0.7), CSS `--phylo-leader-*`. The column is pinned at the right edge of the plot area when zoomed in on x. No effect in a cladogram or the radial layout (not done). Leaders follow the label density rule and are dimmed with their tip.
- **Dim highlights** (#22). Option `highlightStyle: 'band' | 'dim' | 'both'` (default `'band'`, as before) and theme token `dimOpacity` (`--phylo-dim-opacity`, 0.25). With `'dim'` or `'both'`, branches, tips, labels and summaries of clades with no highlighted tip are drawn at `dimOpacity`; a mixed clade keeps full strength. The dim state is a prefix sum over tip ranks, built lazily and only when dimming is on. Columns are not dimmed. `examples/reactree` uses `'dim'` for search, and the playground has a Highlight style setting.
- **Overview wheel** (#33). The wheel over the overview zooms about the tree point under the pointer (it zoomed toward a corner of the window box). Zooming out clamps the anchor into the window, a zoom that cannot go further does not pan, and a horizontal swipe still pans. `ViewState.zoomAtWorld` holds the zoom arithmetic and `zoomBy` shares it.
