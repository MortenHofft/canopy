Method: npm registry JSON, crates.io API, PyPI JSON, shallow git clones of the repos (source read at HEAD), npm tarballs and the phylocanvas.gl source map. Commit dates are HEAD of the shallow clone. GitHub API was not reachable from this session, so release tags/stars are not recorded. Existing repo notes (docs/research/data-layer.md, phylotree-js.md, taxonium.md, phylocanvas-gl.md, react-bio-viz.md) were read first and not redone.

Ops key: RR reroot (E = on edge with position, N = on node only), MP midpoint, LD ladderise, RO rotate/swap, CO collapse by support/length, PR prune to tip subset with unary suppression, SU subtree extraction; extras in brackets. "Support moved" = whether internal-node support labels follow their edge when the root path is reversed.

## Recommendation

1. Keep our own module. No candidate that is licence-compatible (MIT/Apache) covers our op set: patristic and phylotree.js lack edge-position reroot plus support relocation, threshold collapse and prune-to-tip-set; phylo-rs declares reroot but does not implement it.
2. Only patristic shares our data-model idea (typed-array first-child/next-sibling store). It is Apache-2.0 and active, but adopting it would mean a second tree model next to our `TreeSource`; not worth it.
3. Rust/WASM gives no win: the Rust crates are GPL/LGPL/CeCILL (phylotree, newick/sorbus, light_phylogeny), lack the ops (phylo, bio), and our O(n) TS already does 1M tips in under 1 s; WASM would add a copy across the boundary for each op.
4. Support relocation on reroot is handled correctly only by gotree (edge-held support), TreeSwift (`branch_support=True`) and, implicitly, phylocanvas.gl. phylotree.js, PhyloJS and patristic leave support on the node. Keep our "support moves with edges" rule and write a test for it.
5. Borrow tests and behaviour, not code: use TreeSwift and gotree (GPL, so as black-box oracles run outside our code base, not copied) to cross-check reroot/midpoint/collapse/prune outputs on our test trees; copy the idea of patristic's 100k caterpillar deep test; check our Newick edge cases against patristic 0.7.1's changelog list.
6. Midpoint: verify ours is O(n) (two-pass farthest-leaf), not the O(n^2) all-pairs of phylocanvas.gl.
7. If we ever need RF distance or LCA queries, phylo-rs (MIT) and patristic have permissive implementations worth reading.
