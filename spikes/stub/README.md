# stub: the naive reference candidate, and how to write an adapter in 10 steps

`stub/` is a deliberately naive SVG tree viewer (rectangular and radial, no culling, no level of detail) that implements every method of [../CONTRACT.md](../CONTRACT.md). It exists to (a) self-test the runner and (b) be copied as the template for real candidates. It is a lower reference for performance. "source: library" in its events means "reported by the stub's own click handler" (there is no third-party library; the descendant tips come from the shared `TreeModel`).

Files: `spike.json` (deployment and styling metadata), `src/main.tsx` (3 lines: `mountShell(adapter)`), `src/adapter.tsx` (the `View` and the capability report), `src/layout.ts` (node coordinates and SVG strings), `vite.config.ts` (uses `../shared/vite.base.mjs`), `tsconfig.json`, `index.html`.

## Styling template

`src/adapter.tsx` shows the pattern: colours come from `gbifTheme()` / `gbifDarkTheme()` (`../../shared/gbif-theme.ts`), which reads the GBIF tokens at runtime, and are handed to the renderer as CSS custom properties on its root (`themeVars`). For a canvas or WebGL library pass the same resolved values into the library's config instead. Tip labels use `--font-body` (italic for scientific names), highlight and selection use `--color-primary`, bars use the categorical palette. The page chrome (header, cards, buttons, tabs-pill, footer) is the shell's and needs nothing from the candidate. `spike.json` lists what was styled and what could not be; fill it in for every candidate.

## Writing an adapter in 10 steps

1. **Copy the folder**: `cp -r spikes/stub spikes/<name>` (without `node_modules` and `dist`). Rename in `package.json` and `index.html`. Candidates are independent packages, not workspaces.
2. **Pin dependencies**: keep `react`/`react-dom` 18.3.1, `vite`, `@vitejs/plugin-react`, `typescript`; add the library with an **exact** version. `npm install --ignore-scripts`, commit `package-lock.json`. Check the licence and put it in `candidate.license`.
3. **Replace `src/adapter.tsx`'s `View`** with a component that uses the library the way a gbif.org developer would (inside a React component; callbacks wired to props). Keep `src/main.tsx` as is. Do not patch or fork the library; if you must monkey-patch, mark the capability `partial` and explain in `how`.
4. **Fill the container.** `props.size` is the CSS size of the container the shell already sized; the View fills 100% of it. Build the library's input from `props.newick` (clean Newick text) or reuse `props.tree` (shared `TreeModel`: ids, tip sets, lengths). Time library-side parsing and report it as `parseMs`.
5. **Call `props.onReady({ parseMs, tips, notes })`** once, when the library has the data and has issued its first render (in an effect). `tips` is what the library itself reports or draws; the runner checks it against the expected count. The shell waits two animation frames, then resolves `mount()` with `firstRenderMs`.
6. **Report events with `props.emit`** from the library's own callbacks: `{ type, nodeId, isTip, tipIds, source, libraryPayload }`. `nodeId` is `tree.nodeId(preorderIndex)` ('n0' is the root), tip ids are labels as parsed. If the library payload lacks the tip set and you compute it from `props.tree`, set `source: 'adapter-derived'` (the runner then marks S3 `partial`). Never fake an event.
7. **React to props.** Apply `colouredClades`, `highlightedTips`, `focusRequest` (act when `seq` changes), `layout`, `branchLengths`, `columns`, `theme`, `tipLinks` (`null` clears). Map shared node ids to library ids robustly (match by descendant tip sets if the library renumbers). Whatever the library cannot do: leave unimplemented and report `no`.
8. **Assign `props.handleRef.current`** (and null on unmount) with `locate`, `bounds`, `locateCell` returning **client-space CSS px** (see `getBoundingClientRect`), `null` when not drawn or not visible. `locate` must return the point where a real click hits the tip or node marker. These are read-only.
9. **Report all 21 capability keys** in `capabilities` (`CAPABILITY_KEYS` in `shared/types.ts`), `yes`/`partial`/`no` with a `how` that names the mechanism or the reason (missing keys count as `no`). For tip links render `a[href][data-tip-id]` (or an overlay that is one), keyboard focusable. Unmount must remove everything (listeners, workers, GL contexts).
10. **Build and run**: `npm run build && npm run typecheck`, look at it with `npm run dev` (open the URL, use the toolbar, see "Viewing a candidate manually" in [../README.md](../README.md)), then `node spikes/runner/run.mjs --candidate <name> --trees smoke`. Results land in `spikes/results/<name>/`; write `docs/results/<name>.md` from them.
